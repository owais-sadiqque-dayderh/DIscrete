## 1. Bugs and robustness

### 1.1 Background tasks could be lost
**Was:** `capture/screen.py` (`call_later(... create_task(self._flush()))`, `_rotate`) and
`app.py` (`_on_idle`) created tasks without keeping a reference. Python can
garbage-collect such a task mid-flight, and its exceptions were never seen.  
**Now:** `discrete/aio.py::spawn()` keeps a strong reference until the task ends and
logs any failure. Used by the observer, the runtime, the enricher and Bubble
(`BubbleService._spawn` now delegates to it).  
**Test:** `test_spawned_task_survives_gc_and_its_failure_is_logged`.

### 1.2 One slow model call stalled all capture
**Was:** `_capture` ran the vision call while holding `_capture_lock`. With 3 retries,
exponential backoff and a 60 s timeout, the lock could be held for minutes. The retry
loop also slept *after* its final failed attempt.  
**Now:** capture and captioning are separate stages.
- The observer does only local work under the lock (frame hash, AX text walk, OCR),
  then queues a `Capture` = the row to store now (basic caption `"App: Window"`,
  `enrich_state='pending'`) plus an `EnrichJob` (frames + context).
- `capture/enrich.py::Enricher` runs the vision call in a bounded pool
  (`DISCRETE_ENRICH_CONCURRENCY`, default 2) and then fills in the caption, entities
  and the new page fields (§2). If the model fails, the row keeps its basic caption
  (`enrich_state='failed'`, `source='degraded'`). If the model says the frame is useless,
  the row becomes `origin='discarded'`: it drops out of search and statistics but still
  dedups identical frames.
- Retries sleep *between* attempts only (4 s, 8 s), never after the last one.
- Side benefit: **deduplication now happens before the vision call.** A capture that
  collapses into an existing row costs no model call. Before, every capture was
  captioned first and deduped afterwards.
- The runtime (`app.py`) is now a small pipeline: ingest (store row, start enrichment) →
  segment queue (FIFO; waits for that row's caption) → embed once → episode tracker.
  Episodes therefore still see final captions, in capture order.
- On shutdown, captions still in flight are abandoned (rows keep the basic caption),
  queued rows are still assigned to episodes, and no model calls are made on the way
  out. On startup, rows left `pending` by a crash are marked `failed`.

**Tests:** `test_capture_is_queued_without_a_model_call`,
`test_slow_vision_call_does_not_hold_up_the_next_capture`,
`test_enrichment_fills_caption_and_page_fields`,
`test_vision_retries_do_not_sleep_after_the_last_attempt`,
`test_useless_frame_leaves_every_index`,
`test_runtime_embeds_each_observation_once_after_its_caption`.

### 1.3 The app wrote into the source tree
**Was:** `retrieval/gaps.py` appended to `golden/auto_cases.pending.yaml` in the repo.  
**Now:** it writes `$DISCRETE_DATA_DIR/auto_cases.pending.yaml` (`gaps.pending_cases_path()`).
`.gitignore` also covers the old path. Tests run in a temp data dir (autouse fixture),
so they can no longer touch `~/.cache/discrete` either.  
**Test:** `test_pending_cases_are_written_to_the_data_dir`.

### 1.4 Two tests needed a live Mac screen
`test_capture_modules_import_and_find_a_window` and `test_ocr_runs_in_accurate_mode`
are marked `@pytest.mark.display` (marker registered in `pyproject.toml`). CI runs
`pytest -m "not display"`.

### 1.5 Smaller fixes found on the way
- Bubble's vision field-read crashed if the window grab returned nothing; it now
  returns an empty read.
- `llm.embed` raises `LLMError` if the provider returns a different number of
  vectors than texts sent. Previously a mismatch would silently attach vectors to the
  wrong rows.
- `retrieve()` cancels its query-embedding task if planning raises.

## 2. Site-specific rules → structured page fields

**Was:** "list what I opened" depended on pattern-matching free-text captions
(`"switched from … to"`, `"github repository page for"`, `"clicked on a link"`), a
Hacker News headline scraper, and hardcoded exclusions (`"hacker news"`, `"blueprint"`,
`"openrouter"`, `"google.com"`, `"finder"`, `"arc\n"`, `"terminal window"`, `"credits"`,
`".cache"`). Replay hardcoded `"Adobe Illustrator 2026"`. Any change in caption wording
silently broke enumeration.

**Now:**
- The vision prompt (`capture/prompts.py`) returns three more JSON fields:
  `page_title` (the content's own title; for a listing, the listing's name),
  `is_listing` (a feed, front page, results, inbox or folder view), and
  `navigated_from` (the page the user came from, only when both screenshots show it).
  They are stored as columns on `observations`, and `page_title` is in the FTS index.
- `retrieval/pages.py` (new) builds page labels and identities from those fields plus
  ground truth (window title, URL, site) only. It never reads caption prose.
- `retrieval/enumerate.py` (new) uses them:
  - A named source is matched by identity (window title, page title, site, URL).
  - Pages whose `navigated_from` names the source are included even outside the time
    trail (plus a direct `navigated_from LIKE` lookup).
  - For "what did I open/read…" questions, listings are the source and never an item.
    A page reached from a *different* page is not an item from this source.
  - When any page has a recorded source, pages that were only open nearby in time are
    dropped ("provenance beats proximity"). This replaces the hardcoded `blueprint`
    exclusion with a general rule.
  - The evidence pack marks `[listing]` and `from <page>`.
- Removed from `textkit.py`: `_LISTING_URL` (an HN regex), `_NAV_CAPTION`,
  `_DEST_CAPTION`, `_HN_ITEM`, `destination_from_caption`, `hn_headlines`,
  `navigation_caption`, `page_label`, `page_identity`, `is_listing_url`. The file's own
  rule ("no topic-specific constant") holds again.
- Replay: an `app` that looks like a web address becomes `Browser`; a real app name is
  kept. No app is named in code.
- **Guard:** `test_no_site_specific_rules_in_topic_neutral_code` parses `textkit.py`,
  `pages.py`, `enumerate.py`, `hybrid.py` and the replay tool, and fails on any site/app
  literal or caption-phrase literal.

**Rows captured before C6** have no page fields. `discrete backfill-pages` (new) makes
one vision call per such row, using its saved frame when it is still on disk and
otherwise text only, with the old caption as extra context. The caption itself is kept,
so existing evidence quotes still match.

**Measured on a copy of the real store (75 rows, 15 Sep session):**

| Question: "list all the articles I opened from hacker news" | Items |
|---|---|
| Old code (caption regex + HN scraper + hardcoded filters) | 7: OpenArm, **iOS 27**, Linux from Scratch, **auto-vectorization**, frank-386, **Trying to Make a Loop Auto-Vectorize**, 404 Media |
| New code, after `backfill-pages` | 4: Linux from Scratch, OpenArm, frank-386, "Cops Search Thousands of Flock Cameras…" (the 404 Media article) |

The three bold items were never opened. Their frames show the HN list page; the old
code took a headline from the list text or from a guessed caption. One of them was also
a duplicate of another. The new list contains only pages that were actually captured.

## 3. Cost and speed

| Change | Before | After |
|---|---|---|
| Observation embeddings | tracker embedded each row, then the outbox embedded it again (2 calls) | embedded once after its caption, vector stored immediately (`embed_worker.embed_row`); the tracker receives the vector; reuses a stored vector with the same text hash |
| Durable-claim embeddings | once to find candidates, again via the outbox | one batched call per episode; the vector is written with the claim (`create_claim(..., vector=)`) |
| Relation classification | one model call per new durable claim | one call per episode (`RELATE_PROMPT` batches `NEW n` blocks) |
| Bubble reads | shared one connection/lock with every write | separate query-only connection + lock (WAL); `q`/`q1` and all retrieval reads use it |
| Claim evidence in retrieval | one query per claim | one query (`store.first_quotes`) |
| Entity mention backfill | every live claim + its evidence, per promoted entity | live claims + quotes loaded once per run (`live_claims_with_quotes`), mentions inserted in one transaction |
| Alias lookup for fuzzy resolution | all aliases loaded on every call | cached; checked with a one-row fingerprint query (also sees other processes' writes) |
| MinHash signatures | pickled `datasketch` objects; up to 200 unpickled per insert | raw `uint64` bytes; one vectorized numpy comparison |
| Outbox vs. pending captions | would embed the basic caption, then re-embed | skips rows whose caption is still pending |
| Token usage | not recorded | `llm.METER` counts calls/prompt/completion tokens per component; flushed to `metrics` (`llm.<component>.*`) by the runtime every minute and by every CLI command; `discrete stats` prints a table |

Dense-index cache invalidation now happens after commit. Before, a reader could rebuild
the cache between a write and its commit and keep stale vectors.

**What the new meter showed right away (copy of the real store):** the caption
component is almost all of the spend, at about 3,900 prompt tokens per vision call.
gpt-4o-mini bills each image as roughly 2,800 tokens even at `detail=low`. Backfilling
63 rows cost about 249K prompt tokens; everything else combined was about 33K.
Deduping before the vision call (§1.2) is the biggest saving in this commit. See
follow-ups below.

## Behaviour changes to know about
- **`discrete replay-workaa` is gone** → `python tools/replay_workaa.py --fresh`.
- **New command:** `discrete backfill-pages [--limit N]` (run once on pre-C6 stores).
- **New tunables:** `DISCRETE_ENRICH_CONCURRENCY` (2), `DISCRETE_LAST_KEPT_MAX` (512).
- **New `origin` value** `discarded` (frames the vision call judged useless). `stats`
  now says "self/discarded".
- **Captions arrive a few seconds after a capture.** `stats` shows "captions pending".
- **Episode semantic-shift** similarity now uses the stored observation embedding
  (window title, page title, site, caption, screen text up to 2,000 chars) instead of a
  separate caption + 1,000-char embedding. The threshold `EPISODE_SHIFT_SIM` (0.55) is
  unchanged and may want re-tuning.
- **Batched relation calls** compare each new durable claim with *existing* claims.
  Two new claims from the same episode are not compared with each other; offline
  consolidation still merges such pairs.
- The vision call's `max_tokens` went from 400 to 500 to fit the new fields.
