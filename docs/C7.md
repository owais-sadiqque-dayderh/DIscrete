## 1. What is measured

### 1.1 Every model call (`perf_calls`)
`llm.py` wraps each `complete`, `stream`, `embed` batch and `rerank` in one record:
component, model, start time, duration, first-token time (streams only), prompt and
completion tokens, cost in USD, and status (`ok` / `error` / `cancelled`).

- Usage arrives inside the backend (`METER.add_usage`). A context variable holds the
  call in flight, so tokens and cost land on the right record even when calls run
  concurrently (two vision calls at once, the planner beside the query embedding).
- For streams the record is made current only while the backend runs, never across a
  `yield`. A call the consumer makes mid-stream therefore reports into its own record.
- Streams now send `stream_options.include_usage`. Before this, the writer's
  streamed tokens were never counted.
- `METER` running totals gain a `cost` field, so `discrete stats` shows `cost $`
  per component.

### 1.2 Pipeline stages (`perf_samples`)
Labels are what `bench` prints.

| Stage | Where | Measures |
|---|---|---|
| `capture.local` | `screen._capture` | all local work before the queue (hash, text, frame save) |
| `capture.text` | `screen._capture` | AX walk + OCR (`n` = characters read) |
| `ingest.stored` | `app._ingest_loop` | capture queued → row written |
| `enrich.wait` | `enrich._run` | waiting for a vision slot (`ENRICH_CONCURRENCY`) |
| `enrich.vision` | `enrich._run` | the vision call, retries included (`n` = frames sent) |
| `enrich.total` | `enrich._run` | row stored → final caption |
| `segment.embed` | `app._segment` | embedding one capture |
| `segment.lag` | `app._segment` | row stored → placed in an episode (end-to-end ingest) |
| `embed.outbox` | `drain_outbox` | one outbox drain (`n` = rows) |
| `draft.episode` | `pipeline.draft_episode` | drafting one episode (`n` = claims added + reinforced) |
| `consolidate.run` | `run_consolidation` | one consolidation run |
| `retrieve.plan` / `.search` / `.rerank` / `.mmr` / `.enumerate` / `.total` | `hybrid.retrieve` | each search step |
| `bubble.field_read` / `.retrieve` / `.first_chunk` / `.write` / `.total` | Bubble engine and service, `discrete ask` | hotkey → text typed |

**Event counters** (a sample with no duration) come from the observer's and enricher's
in-memory stats. They are flushed as deltas every minute, e.g. `capture.frame_dup`,
`capture.suppressed`, `enrich.dropped_useless`, `enrich.vlm_attempts_failed`.
**`runtime.start` / `runtime.up`** mark each `discrete run`; they give `--since
last-run` and daemon uptime.

### 1.3 Sources
Every record carries the command that made it (`PERF.source`): `live` (the daemon),
`ask`, `process`, `consolidate`, `backfill-pages`, `eval`, `query`, `bench`. The report
leaves out `eval`, `query` and `bench` by default: measuring must not show up as
pipeline cost.

### 1.4 Storage and retention
Migration **m005_perf_log** adds `perf_calls` and `perf_samples` (indexed on time).
Retention prunes rows older than `DISCRETE_PERF_TTL_DAYS` (90). The buffers are
in memory, capped at 50K records each, and written with the existing usage flush:
every minute in the daemon, and at the end of every CLI command.

## 2. `discrete bench`

```
discrete bench [--since all|last-run|90m|6h|2d|"2026-09-30 14:00"] [--until …]
               [--source live,ask] [--eval] [--save NAME] [--compare NAME [NAME2]] [--json]
```

Sections of the report:
- **COST**: total, per active hour, per capture, and a per-component table (calls,
  errors, tokens per call, $ per call, cost share, p50/p90 latency).
- **LATENCY**: every stage above, as n / p50 / p90 / max in ms.
- **CAPTURES**: rows by source, duplicates folded in, caption outcomes, AX vs OCR,
  counters, vision calls per active hour.
- **QUALITY**: hit@k, MRR, refusal accuracy and grounded rate from `golden/cases.yaml`.
  Only with `--eval`; the eval's own model calls are tagged `eval`.
- **STORAGE**: database and frames size, MB per active hour.

**Active time** is the time covered by captures, bridging pauses of up to
`IDLE_THRESHOLD_S` (5 min). Heartbeats capture at least every 10 min while the
screen is in use, so reading without clicking still counts. Per-hour numbers use
this, not wall time.

**Snapshots** are plain JSON in `bench/NAME.json` (committed with each step). They
hold every number, the git revision (and whether the tree was dirty), each
component's model, and every tunable in `config.T`. `--compare A` lines up the
headline numbers of A against the current report, marks each better or WORSE by
its direction, and lists any config that differs.

## 3. Other changes
- `golden/cases.yaml` is now a documented template (empty list). The three old
  placeholder cases were written for an empty store.
- `discrete stats` usage table gains a `cost $` column.
- `discrete run` now stops cleanly on SIGTERM (`kill`, launchd) as well as Ctrl-C.
  Before, SIGTERM killed it outright: in-flight work was not closed and the last
  minute of measurements was lost. Found while testing: a `run` started in the
  background by a script ignores SIGINT.

## 4. Any model from `.env`, no code changes

**Why:** on 2026-09-30 the chat models were switched in `.env` to
`meta/muse-spark-1.3-contributor`, a reasoning model. Reasoning is mandatory for it
(it can't be switched off), and its thinking tokens count against `max_tokens`. With
the code's limits (caption 500, entity check 30, planner 300, consolidation 400) it
thought until the limit and returned an empty reply. All 25 captures in that run lost
their caption: 72 vision calls, each retried as "unparseable JSON".

**Now:** each chat component takes request settings from `.env`. They cascade like
the model name: the component's own prefix, then `CORE_LM_`. Embeddings and rerank
never inherit chat settings.

| Setting | Effect |
|---|---|
| `<P>_EXTRA_TOKENS` | added to every `max_tokens` (room to think) |
| `<P>_REASONING_EFFORT` | `minimal`/`low`/`medium`/`high`; sent as `reasoning.effort` to OpenRouter, `reasoning_effort` elsewhere |
| `<P>_TEMPERATURE` | a number overrides the code's value; `off` never sends one |
| `<P>_JSON_MODE` | `false` skips `response_format` |
| `<P>_TIMEOUT_S` | per-request timeout |
| `<P>_EXTRA_BODY` | JSON merged into every request (provider routing, reasoning budget, …) |

- A malformed value stops the command with the variable's name (`ConfigError`).
- An empty reply that stopped at the token limit raises `TokenLimit`, naming the two
  settings to change. Captions don't retry it, since the same request would fail
  again. Streams check this too.
- **`discrete doctor --models`** sends one real request per component, using that
  component's tightest real call (real caption prompt and screenshot, the 30-token
  entity check, the planner against `PLAN_TIMEOUT_S`, a streamed writer reply,
  embeddings, rerank). It reports OK/FAIL, time, tokens used against the limit,
  cost, and the fix.
- These settings are part of bench snapshots (e.g. `caption.reasoning_effort`), so
  they show up under "Config differences" in `--compare`.
- `.env` and `.env.example` now list every model setting and the most useful
  `DISCRETE_*` tunables with their defaults.

Muse Spark on one real screenshot:

| Settings | Caption |
|---|---|
| defaults | empty (500/500 tokens thinking) |
| `REASONING_EFFORT=low` | empty |
| `REASONING_EFFORT=minimal`, `EXTRA_TOKENS=1000` | OK, ~470 tokens, ~12 s, $0.0003 |
| `EXTRA_TOKENS=1500`, default effort | OK, ~1,850 tokens, 21 s, $0.0005 |
| gpt-4o-mini (for reference) | OK, 3.6 s, $0.0011 |

The planner (UTILITY_LM) answered correctly in 13 s but Bubble waits 4 s
(`PLAN_TIMEOUT_S`), so with Muse Spark Bubble searches without a plan. Use a fast
model for UTILITY_LM, or accept that.

## Known limits
- Cost is what the provider reports. A provider that sends no `usage.cost` shows
  "cost missing on N calls" and totals undercount; OpenRouter sends it.
- Storage is the current size, not a windowed number.
- Stage samples from a crashed run are lost back to the last minute's flush.
